Resumen de cambios y experimentos realizados

1. Limpieza y carga de datos
- Se mantuvo la carga masiva de todos los .txt desde data/Stocks.
- Se añadió esquema explícito para evitar inferSchema.
- Se extrae Symbol desde el nombre del archivo.
- Se eliminan filas con OHLC nulos.
- Se filtran precios inválidos: Open, High, Low, Close > 0 y Volume >= 0.
- Se añaden comprobaciones OHLC: High >= Open/Close/Low y Low <= Open/Close.
- Se filtran símbolos con menos de 60 registros.

2. Cambio metodológico principal
- Al principio se usaba randomSplit + CrossValidator.
- Después se cambió a train / validation / test temporal:
  - train: fechas < 2015-01-01
  - validation: 2015-01-01 a 2016-01-01
  - test: fechas >= 2016-01-01
- Esto evita leakage temporal y es más realista para datos financieros.
- Se sustituyó CrossValidator por grid search manual usando validation.

3. Features temporales
- Se añadieron variables cíclicas:
  - DateMonthSin / DateMonthCos
  - DateDaySin / DateDayCos
  - DayOfWeekSin / DayOfWeekCos

6. Clasificación

6.1 Cambio de objetivo
- Se creó main_clasificacion.py.
- En vez de predecir el retorno continuo, se predice si el retorno futuro a 20 días será positivo o negativo.
- Target:
  - LogReturn20 = log(Close futuro a 20 días / Close actual)
  - label = 1 si LogReturn20 > 0
  - label = 0 si LogReturn20 <= 0

6.2 Modelos de clasificación implementados
- MajorityBaseline:
  - predice siempre la clase mayoritaria del train.
- LogisticRegression:
  - con StandardScaler dentro de Pipeline.
- RandomForestClassifier:
  - modelo no lineal basado en árboles.
- GBTClassifier:
  - gradient boosted trees.

6.3 Evaluación de clasificación
- Se usan métricas en validation y test:
  - accuracy
  - weighted F1
  - weighted precision
  - weighted recall
  - AUC
- Además se añadieron informes detallados para los mejores modelos:
  - matriz de confusión
  - precision por clase
  - recall por clase
  - F1 por clase
  - balanced accuracy
  - porcentaje de predicciones positivas y negativas

6.5 classification_results_20260424_034529

6.6 Resultado final de clasificación
- Archivo:
  - classification_results_20260424_034529.csv
- Mejores modelos por F1 de validation:
  - LogisticRegression: regParam=0.01, elasticNetParam=0.0
  - RandomForestClassifier: numTrees=50, maxDepth=10
  - GBTClassifier: maxDepth=5, maxIter=20
- Mejor F1 de validation:
  - GBTClassifier con val_f1 = 0.4586
- Mejor AUC de test:
  - RandomForestClassifier con test_auc = 0.5624
- En general, los modelos mejoran al MajorityBaseline, aunque el problema sigue siendo difícil porque las métricas están cerca del baseline.

9. Conclusión general
- Se empezó con una regresión básica usando randomSplit y CrossValidator.
- Se corrigió la metodología usando validación temporal.
- Se añadieron modelos no lineales y baseline.
- Se vio que la regresión tiene problemas de generalización.
- Se cambió a clasificación de dirección del retorno, que es más razonable para el problema.
- Se añadieron métricas más interpretables, especialmente matriz de confusión y métricas por clase.
- El mejor clasificador según validation F1 fue GBTClassifier, aunque RandomForest tuvo mejor AUC en test.
